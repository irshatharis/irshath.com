What I do

From the first commit to the first customer.

  1. Idea to launch

    You have an idea and need it built properly. I shape the scope with you, choose the stack and ship the first version, including the parts that have to be right from day one: sign-in, payments, permissions and data.

  2. Foundations for growing teams

    Your team is starting to build, or already moving fast with AI tools. I set up the monorepo, design system, data layer and conventions so every engineer and every agent follows the same patterns.

How I work

AI writes fast. I make sure it writes right.

Most AI-built codebases look fine for a month. Then every change breaks something else. I set projects up so that does not happen.

  1. Rules become checks.

    When a convention matters, it becomes a lint rule, a type or a test, so neither people nor agents can quietly break it.

  2. Done means it runs.

    Agents drive the real app in a browser and keep screenshots as evidence. A feature is done when it works, not when it compiles.

  3. The repo explains itself.

    Architecture notes and agent guides live next to the code, so a new engineer or a new agent is useful on day one.

  4. Housekeeping is part of the job.

    Dead code, duplicated patterns and stale docs get cleaned up as the work goes, not saved for a rewrite.
